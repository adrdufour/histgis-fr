# Le recensement de 1968 — ce que les fascicules contiennent

Mesuré le 15 août 2026, sur les 83 fascicules déposés sous `sources/rp1968/`.
Index : `cog1968/index_fascicules.py` → `fascicules_1968.csv`.

---

## En un mot

**1968 est plus facile que 1954, et d'un cran, pas d'une nuance.** Le tableau
III porte le **code INSEE de la commune**. Là où 1954 obligeait à apparier
38 000 noms — et en laissait 7 576 sur le carreau — 1968 donne la clé de
jointure directement.

### La couche texte : les liminaires oui, les tableaux non

Chaque PDF porte un texte partiel — de 10 000 à 14 000 caractères pour une
trentaine de pages, soit environ 400 par page, ce qui est un ordre de grandeur
en dessous d'un tableau de communes. La mesure page par page le confirme : les
liminaires sont lisibles, **les pages de tableaux sont à zéro caractère**.

Utile quand même : le département se lit sans OCR, ce qui a permis l'index.

## La structure du tableau III

Une ligne par commune, dans cet ordre :

```
[pop. 1962] [pop. 1962 sans doubles] [arr] [canton] [code INSEE] Nom.  [pop. 1968] …
```

Exemple lu sur la page 21 du fascicule de l'Aisne :

```
219  219   4  35  562  Nouvron-Vingré.   221  221  124  97  …
215  215   5  16  563  Noyales.          185  185  154  31  …
321  321   4  31  564  Noyant-et-Aconin. 367  367  359   8  …
```

**Le nombre à trois chiffres est le code INSEE de la commune** — vérifié sur
neuf communes prises au hasard, **9 concordances sur 9** avec `noms_geofla`.
C'est cohérent : les codes INSEE sont attribués dans l'ordre alphabétique, et
la colonne progresse alphabétiquement.

### Quatre garde-fous que 1954 n'offrait pas

| | |
|---|---|
| **le code INSEE** | plus d'appariement par nom, donc plus de 7 576 orphelins |
| **le code INSEE croît** | monotone dans la page : un chiffre mal lu se détecte sur ses voisins |
| **le tableau II** | population **et nombre de communes** par canton — une recette de contrôle fournie par la source |
| **l'en-tête de page** | « AISNE (02) » sur chaque page de tableau : le département ET son code, à chaque feuille |

Le dernier point vaut d'être noté : l'index par page de titre a demandé trois
essais et une correction manuelle. L'en-tête des pages de tableau aurait donné
la réponse directement, avec le code numérique en prime. **La bonne clé était
sur la page suivante.**

## La mesure de faisabilité

Une page OCRisée, comparée à la composition cantonale de 1940 déjà en base.

| | |
|---|---|
| lignes lues sur la page | 39 |
| **canton conforme à 1940** | **31 — 79 %** |
| divergent | 8 |
| commune absente de la base | 0 |

**Et ce chiffre est un plancher, pour trois raisons.** L'OCR a tourné en
**anglais**, faute du paquet `tesseract-ocr-fra` dans le bac à sable. Aucune
des corrections écrites pour 1954 n'a été appliquée — ni la table des sosies,
ni le contrôle de monotonie, ni le redécoupage. Et le rendu était brut, sans
prétraitement.

### Les huit divergences

```
02568 OIGNY-EN-VALOIS   lu 0216   base 0236
02569 OISY              lu 0287   base 0237
02576 OSLY-COURTIL      lu 0285   base 0235
02607 PLOISY            lu 0281   base 0231
02608 PLOMION           lu 0284   base 0234
```

Le motif saute aux yeux : **le 3 initial est lu 8, 2 ou 1**. Sept divergences
sur huit portent sur ce seul chiffre.

**Mais attention, et c'est la leçon de 1954** : un transfert réel de commune
entre 1940 et 1968 produirait exactement la même trace. Le motif rend
l'explication par l'OCR très probable ; il ne la prouve pas. Les 311
« transferts » de 1954 avaient tous des codes valides et des cantons réels, et
la géométrie en a réfuté 227. **Ne pas conclure sur un motif : mesurer sur un
département entier, avec le tableau II comme arbitre.**

## `extrait_1968.py` — écrit, et mesuré

**La chaîne d'OCR de 1954 n'a pas été réécrite, elle est importée.**
`page_texte`, `nettoie_nom`, `SOSIES` viennent de `cog1954/extrait_1954.py` :
pdftoppm 300 dpi gris, tesseract `--psm 6`, multiprocessing. Si elle est
améliorée là-bas, 1968 en profite sans rien changer ici.

Seule la **grammaire de la ligne** est neuve, et la mesure dit pourquoi elle
devait l'être : lancer le parseur de 1954 tel quel sur un fascicule de 1968
rend **2 lignes sur 13 pages**. La machinerie tournait, la grammaire ne collait
pas — deux colonnes de population et le code INSEE s'intercalent.

### Résultat sur l'Aisne, 7 pages — anglais puis français

Deux passages, **une seule variable changée entre les deux** : la langue.

| | anglais | français |
|---|---|---|
| lignes lues | 258 | **288** |
| canton conforme à 1940 | 232 | **267** |
| **taux** | 89,9 % | **92,7 %** |
| divergent | 26 | 21 |
| commune inconnue de la base | 0 | **0** |
| le nom confirme le code INSEE | 89 % | 91 % |
| cantons distincts | 41 | 44 |

Le premier saut, de 79 % à 89,9 %, venait de la **grammaire** — même moteur,
même langue, mêmes pages. Le second, à 92,7 %, vient de la **langue** — même
grammaire. Chaque gain est attribuable parce qu'une seule chose a bougé à la
fois.

### Les 44 cantons : l'alerte se dissout

Le français lit plus de lignes et trouve **plus** de cantons distincts — 44
contre 41 — alors que l'Aisne en comptait 37 en 1940. Le compte semble
empirer ; il n'en est rien.

Neuf codes ne sont vus qu'une ou deux fois, et huit d'entre eux sont
**structurellement impossibles** : 50, 53, 54, 55, 60, 82, 85, 94, dans un
département qui n'a jamais dépassé 37 cantons. Les retirer ramène le compte à
**36**, à un canton du chiffre attendu.

D'où une borne ajoutée au script : `bornes_cantonales()` calcule, pour chaque
département, le plus haut code de canton connu en 1940 — 91 départements
couverts, 37 pour l'Aisne.

**Elle signale, elle ne supprime pas**, et la nuance est tout le sujet. Un
canton créé entre 1940 et 1968 porterait justement un numéro au-delà de la
borne. Filtrer dessus reviendrait à faire de l'étalon un paramètre et à rendre
invisible la découverte même qu'on cherche — la faute que `METHODE.md` interdit
depuis le contrôle Gay. La colonne `hors_borne` marque la ligne ; **le tableau
II tranchera**.

| l'Aisne en compte | 816 |

### Le résultat qui compte : 37 cantons, et les bons

Une fois les 23 lignes `hors_borne` mises de côté :

* **37 cantons distincts** — exactement le compte de 1940 ;
* **les codes 01 à 37 sont tous présents**, aucun manquant ;
* **aucun canton vu une ou deux fois seulement** — plus une seule scorie.

Trois recettes indépendantes qui tombent juste ensemble. Le cadre cantonal de
l'Aisne n'a donc pas bougé entre 1940 et 1968, du moins pour ce que la lecture
atteint.

### La borne n'a rien masqué, et c'est vérifiable

C'était le risque assumé : écarter les codes au-delà de 37 pouvait faire
disparaître un canton créé après 1940, qui porterait précisément un numéro
au-delà. Les 15 codes rejetés sont :

```
50 51 52 53 54 55 57 60 80 81 82 84 85 86 94
```

**Aucun 38, 39 ni 40.** Tous sont très au-delà de la borne, et chacun renvoie à
un canton de 1940 dont il ne diffère que par le chiffre des dizaines — 50 pour
30, 85 pour 35, 94 pour 24. Une création se serait signalée juste au-dessus de
37 ; il n'y a rien là.

La borne a donc capté du bruit et rien que du bruit. **Ce n'est pas une
propriété de la borne, c'est un fait mesuré sur ce département** — à revérifier
ailleurs, notamment là où des créations sont attendues.

### Ce qui reste ouvert

**38 divergences** avec 1940, dont 17 à un seul chiffre près et 21 à deux. Les
premières sentent l'OCR, les secondes moins. Elles ne pourront être départagées
ni par la borne ni par la monotonie : il y faut le tableau II.

**20 % des communes ne sont pas lues** — 162 sur 816. Le taux est le même qu'en
1954, ce qui suggère une cause commune : la grammaire exige un point après le
nom et un nombre après le point. Les lignes de chef-lieu, les renvois et les
totaux y échappent. C'est le second levier, après le tableau II.

## Rappel de portée

1968 est **un jalon daté à l'intérieur du trou 1941-1998**, pas le trou comblé.
Il donne la carte cantonale à une date, entre 1954 et 1999. Les décrets du JO
(`cantons/composition_decrets.py`) donnent les mouvements entre les jalons. Ni
l'un ni l'autre ne couvre 1987-1998, où l'annexe VII s'arrête et où le COG ne
recense que 66 changements, tous postérieurs à 1995.

## Où en est le tableau II — checkpoint du 15 août 2026 au soir

**29 cantons lus sur 37, 5 arrondissements sur 5**, en OCR français.

**Saint-Quentin passe les deux recettes** : 127 = 127 sur le TOTAL imprimé,
7/7 sur le nombre de cantons annoncé. C'est la preuve que la méthode tient là
où l'OCR est propre ; les échecs sont localisés, pas structurels.

### Trois corrections acquises

1. **Ancrage numérique et non textuel.** Les points de conduite sont lus comme
   des lettres et emportent le nom du canton. 1 canton sur 37 au premier jet.
2. **Ancrage en fin de ligne.** Le bord gauche est le fond de reliure, la zone
   la plus déformée. Exiger les populations de 1962 en tête coûtait la moitié
   des lignes.
3. **Sélection de page élargie.** La page 8 porte « ARRPONDISSEMENTS », avec un
   `p` parasite : la page entière était sautée, Soissons et Vervins perdus. Le
   tableau ne tient pas sur une page, et rien ne le disait.

### Deux défauts restants, diagnostiqués et non corrigés

**Le code de canton est mal extrait.** Cinq lignes différentes ressortent sous
le code `10`, avec des noms distincts (« Capelle », « CROZOY-SUT-SEITE »…).
`CODE` prend le premier groupe de deux chiffres du fragment illisible, or ce
fragment contient aussi des débris de populations. C'est la cause directe du
`0/29 cantons au compte juste` : la confrontation compare des cantons mal
identifiés. **À reprendre : lire le code par sa position relative** — il suit
les deux populations de 1962 et précède le nom — plutôt que par « le premier
qui vient ».

**Des lignes TOTAL fuient encore.** Vervins apparaît deux fois dans la recette
1, avec 132 puis 831 ; 831 est le total du département, pris pour un total
d'arrondissement. D'où les 923 communes annoncées, alors que l'Aisne en compte
816. Le détecteur arithmétique `n >= somme du bloc` ne distingue pas un total
d'arrondissement d'un total général.

**Conséquence à retenir** : tant que ces deux défauts tiennent, le chiffre
« 265 communes manquantes » ne veut rien dire — son premier terme est gonflé.
Ne rien conclure de cette confrontation avant de les avoir corrigés.

## La question posée au tableau II reçoit sa réponse — 15 août 2026

Le tableau II était appelé pour trancher une question précise : **les 20 % de
communes non lues sont-elles réparties ou concentrées ?** L'enjeu n'est pas
cosmétique. Réparties, la composition est *incomplète* ; concentrées sur
quelques cantons, elle est *fausse* pour ceux-là.

Dix cantons ont pu être identifiés de part et d'autre — code lisible dans le
tableau II, code lisible dans le tableau III. C'est peu, mais cela suffit,
parce que le résultat est sans nuance :

| | |
|---|---|
| cantons confrontés | 10 |
| **écart négatif — lecture incomplète** | **10** |
| écart positif — commune en trop | **0** |
| écart nul | 0 |

**Aucun écart positif.** Le tableau III ne met jamais dans un canton une
commune qui n'y appartient pas : il en oublie, il n'en invente pas.

Et le manque est **réparti**, pas concentré :

```
   23  Nouvion-en-Thiérache     4/10    40 %
   31  Soissons                13/21    62 %
   08  Château-Thierry         15/21    71 %
   21  Neufchâtel-sur-Aisne    21/28    75 %
   24  Oulchy-le-Château       21/28    75 %
   26  Rozoy-sur-Serre         25/30    83 %
   03  Bohain-en-Vermandois    12/14    86 %
   11  Coucy-le-Château        28/32    88 %
   19  Crécy-sur-Serre         19/20    95 %
   15  Fère-en-Tardenois       23/24    96 %
```

De 40 % à 96 %, **aucun canton à zéro**. Sur ces dix cantons, 47 communes
manquent sur 228 — soit **21 %**, la même proportion que les 20 % mesurés sur
le département entier. L'échantillon est donc représentatif.

**Conclusion, et c'est ce qu'on venait chercher** : la composition cantonale de
1968 telle qu'elle est lue est **incomplète mais non fausse**. Elle peut être
posée en base avec une réserve quantifiée, plutôt que d'attendre une lecture
parfaite.

### Une hypothèse de méthode réfutée en chemin

Le recours au nom — retrouver le code d'un canton illisible via la nomenclature
de 1940 — devait appliquer la règle du projet : *deux signaux faibles et
indépendants valent mieux qu'un signal fort*. Il n'a rien rapporté : **1 code
sur 29**.

La raison mérite d'être retenue. **Le code et le nom ne sont pas des signaux
indépendants** : ils sont sur la même ligne, dans la même zone abîmée du scan.
Quand l'OCR détruit l'un, il détruit l'autre. Les lignes à code lisible ont un
nom lisible ; celles à code perdu donnent « MIRE RS PRES RE Re ».

La règle des deux signaux vaut quand les signaux ont des **causes de défaillance
différentes** — la fréquence et la position des ark, par exemple, qui ont bien
départagé l'Isère. Deux lectures de la même ligne physique n'en font qu'un.
